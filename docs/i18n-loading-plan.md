# 按语言加载方案（本轮未实施）

目前有 14 种语言：中、英、意、法、德、西、葡、阿拉伯、印地、乌尔都、孟加拉、日、韩、俄。中英以外是 12 种，不是需求附件中的 13 种。

## 建议的改法

1. 保留 `src/i18n.json` 为编辑入口。构建时分别输出带内容哈希的 `locales/en.<hash>.json` 等 14 份文件，另生成代码、显示名、方向和文件名的轻量清单。
2. 英文正文继续直接输出到 HTML。首次加载根据有效的 `?lang=`、已保存的选择、英文默认值这个顺序确定语言。英文访客无需下载其他词典。中文等访客只下载一份选中语言的词典。
3. 切换语言时先获取、校验完整词典，再一次性更新正文、`lang`、`dir`、元信息和 URL。请求失败保留当前语言；快速切换用请求序号或 `AbortController` 忽略旧响应。已加载词典缓存在内存中，哈希 URL 让浏览器安全复用缓存。
4. 加载完成前保持现有页面，初次访问则在 `<head>` 确定语言后控制首次显示，避免先画英文再切换。不能只把当前内联词典替换成一个异步 `fetch`。

## 对首屏的影响

英文下载量会减少，但非英文首屏多一次词典请求。应实测压缩后的传输量和慢速网络下的首次显示时间，不能只看 JSON 文件体积。可以在很小的引导脚本中预加载目标词典；不要预加载全部语言。语言切换不应重新请求已经显示的图片。

本轮仅将首次翻译提前到内联初始化，并等待现有字体完成首次布局。词典仍全量内联，没有实现上述拆分、网络请求或缓存机制。

## SEO 与英文闪烁

GitHub Pages 不会按查询参数返回不同 HTML。因此 `/?lang=zh` 的原始响应仍是英文；不能保证不运行 JavaScript 的爬虫读取中文。本轮为全部语言添加互相对应的 `hreflang`，并在初始化时生成唯一的、保留语言参数的 canonical，避免把所有语言都指向英文。无脚本的英文兜底使用英文 canonical。

若下一轮需要可靠的非英文原始 HTML，建议在构建时预渲染 `/en/`、`/zh/` 等路径，把本语言正文和元信息直接写入页面。旧的查询参数链接保持兼容。这样首屏无需等翻译请求，原始 HTML 也与 canonical、`hreflang` 一致。该路由与输出结构调整应单独评审，本轮不实施。

单纯的客户端按需加载会延长非英文页面进入搜索引擎渲染队列后的处理过程。没有任何 canonical 设置能保证搜索引擎最终选用指定 URL，部署后仍需在 Search Console 查看结果。依据：[Google 的 JavaScript SEO 文档](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)、[多语言版本说明](https://developers.google.com/search/docs/specialty/international/localized-versions)。
